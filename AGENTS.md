# AGENTS.md

Инструкции для AI-агентов, работающих с этим репозиторием.

## Проект

Searcher — API для поиска товаров в каталоге. Проект находится на ранней стадии: сейчас есть заготовка FastAPI, модель `Product`, миграции и импорт CSV. Не считать поиск, фильтры или полноценные CRUD-эндпоинты уже реализованными. План развития описан в `ROADMAP.md`.

## Стек

- Python 3.12+
- FastAPI
- SQLAlchemy 2.x
- Alembic
- PostgreSQL через `psycopg`
- Зависимости: `pyproject.toml`, lock-файл: `uv.lock`

## Структура

- `app/main.py` — приложение FastAPI и HTTP-маршруты.
- `app/models.py` — ORM-модели SQLAlchemy.
- `app/database.py` — подключение к БД, `SessionLocal` и декларативный `Base`.
- `migrations/` — конфигурация и версии Alembic.
- `scripts/import_products.py` — импорт каталога из `data/styles.csv`.
- `check_db.py` — ручная проверка подключения к PostgreSQL.
- `test_product.py` — ручной черновой скрипт, а не автоматизированный тест.

## Команды

Выполнять из корня репозитория. В Windows учитывать, что README содержит команды PowerShell, а агент может работать через Git Bash.

```bash
pip install -e .
fastapi dev app/main.py
alembic upgrade head
alembic current
alembic revision --autogenerate -m "описание изменения"
python check_db.py
python -m compileall app scripts
```

Для проверки API после запуска: `http://127.0.0.1:8000/docs`.

Не запускать `python scripts/import_products.py` без явного разрешения пользователя: скрипт удаляет все записи из `products` перед загрузкой CSV.

## Правила изменений

- Сначала читать затрагиваемый код и соседние файлы; сохранять принятые в них структуру и стиль.
- Ограничиваться задачей пользователя: не делать массовое форматирование, рефакторинг или исправление unrelated-кода.
- Не добавлять зависимости без необходимости; перед использованием библиотеки проверять `pyproject.toml` и импорты проекта.
- При изменении схемы БД обновлять модель и создавать отдельную миграцию Alembic. Автогенерированную миграцию проверять вручную, включая `upgrade()` и `downgrade()`.
- `migrations/env.py` импортирует `app.models` и использует `Base.metadata`; новые модели должны попадать в метаданные до автогенерации.
- Сохранять совместимость публичных API. Если задача требует ее нарушить, явно сообщить об этом пользователю.
- Не раскрывать и не размножать учетные данные БД. Сейчас подключение задано в `app/database.py`; реальные секреты не должны попадать в новые файлы или вывод.
- Не выполнять коммиты, push, сброс истории и другие необратимые Git-операции без запроса пользователя.

## Проверка

- Тестовый фреймворк и автоматизированный набор тестов пока не настроены; `test_product.py` нельзя выдавать за такой набор.
- После изменений запускать доступные релевантные проверки, как минимум синтаксическую компиляцию затронутых пакетов.
- Изменения API проверять реальными HTTP-запросами, а изменения БД — миграциями и запросами к БД, когда PostgreSQL доступен.
- Если проверка требует недоступный сервер или БД, прямо указать, что именно не удалось проверить; не заявлять об успешном тестировании.
- Не создавать новые тестовые или вспомогательные файлы без необходимости и запроса пользователя.

## Актуальность документации

При изменении команд, зависимостей, структуры проекта или описанных здесь правил синхронно обновлять `AGENTS.md` и затрагиваемые разделы `README.md`. Более специфичные вложенные `AGENTS.md`, если появятся, имеют приоритет для своих каталогов.
